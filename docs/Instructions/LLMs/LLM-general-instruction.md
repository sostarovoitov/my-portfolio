!!! info "Назначение"
    Методика описывает алгоритм эффективного ведения диалога с LLM в рамках одного чата: от формирования первичного промпта до получения качественного решения задачи, либо до появления признаков деградации контекста (постепенной потери моделью части ранее заданной информации в диалоге, приводящей к ухудшению качества ответов).

#### 1. Формирование первичного промпта

* Проверить личную базу знаний на предмет промптов или саммари прошлых чатов, которые могут быть полезны для написания промпта по задаче;
* Самостоятельно собрать все иные релевантные сведения по задаче и сформировать первичный промпт на основе [шаблона](prompt-template.md). Неактуальные разделы шаблона следует исключить.

#### 2. Улучшение первичного промпта (опционально)

* При работе со сложными многоэтапными задачами или неуверенности в структуре промпта пропустить первичный промпт через [выбранный мета-промпт](meta-prompts.md) в отдельном чате для его улучшения.

#### 3. Получение первичного результата

* Создать новый чат, используя подготовленный на предыдущих шагах промпт, и дождаться ответа модели.

#### 4. Оценка качества первичного результата

Сравнить полученный результат с [критериями качества](QA.md):

* При несоответствии результата критериям первого уровня вернуться к шагу 1 и переработать первичный промпт;
* При несоответствии результата критериям второго или третьего уровня перейти к шагу 5 и уточнить результат в текущем диалоге;
* В случае, если полученный результат содержит качественное решение задачи, завершить диалог.


* Промпт, обеспечивший качественный результат, рекомендуется сохранить в личную базу знаний.

!!! warning "Внимание"
    Если автоматически сгенерированное название не отражает суть задачи, следует переименовать чат.

#### 5. Развитие диалога и мониторинг деградации контекста

##### Развитие диалога

* Итеративно уточнять и углублять результат с помощью [специализированных техник](quality-improvement-technics.md). Качество каждого нового ответа модели оценивать по тем же критериям, что и первичный результат;
* Переходить к смежным темам по своему усмотрению с использованием техники [смены темы](pivot.md);
* При получении качественного решения задачи завершить диалог.

##### Мониторинг контекста 

Отслеживать признаки деградации контекста:

* Для рядовых чатов при первых признаках деградации контекста (например, ответы стали заметно проще или короче, модель забывает детали из начала чата, начинает противоречить сама себе) использовать [подходящий промпт для создания рабочего саммари](summary.md) и перейти к шагу 6;
* Для особо важных чатов создавать рабочие саммари регулярно, даже если признаков деградации пока нет. Провести быструю проверку рабочего саммари на явные пропуски и искажения, при необходимости внести ручные корректировки, и сохранить его. При первых признаках деградации контекста создать последнее рабочее саммари и перейти к шагу 6.

!!! warning "Внимание"
    Промпты для создания саммари всегда запускаются в отдельных новых чатах.

#### 6. Подготовка к миграции

Подготовить итоговое саммари для переноса важнейшего контекста диалога в новый чат:

* Для рядовых чатов проверить созданное в п. 5 рабочее саммари по [чек-листу](summary-QA.md). В случае успешной проверки использовать его как итоговое саммари, в ином случае самостоятельно выявить упущенные детали, дополнить ими саммари и повторно пройти проверку;
* Для особо важных чатов проверить последнее созданное в п. 5 рабочее саммари по [чек-листу](summary-QA.md). Если чек-лист не пройден, дополнить его важной информацией из предыдущих рабочих саммари и самостоятельно выявленными упущенными деталями. Повторить проверку до полного выполнения чек-листа.

#### 7. Перенос контекста

Вернуться к шагу 1, используя итоговое саммари для описания контекста/входных данных в новом первичном промпте.
