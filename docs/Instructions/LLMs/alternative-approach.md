#### 1. Описание подхода

В предыдущих статьях описывается способ классификации диалогов, основанный на создании базы во внешнем сервисе. Если для вашего рабочего процесса такой подход избыточен, можно воспользоваться упрощенной системой классификации чатов непосредственно внутри экосистемы каждой LLM.

Система основана на применении префиксов. Префикс добавляется к названию диалога и состоит из двух элементов:

`[Статус]` `[Предметная область диалога]`

**Статусы:**

* **[P1]** — активные диалоги, имеющие высокий приоритет;

* **[P2]** — активные диалоги, имеющие средний приоритет; 

* **[ARC]** — диалоги, завершившиеся по объективным причинам (задача выполнена, событие прошло) и содержащие ценный результат;

* **[REF]** — справочные диалоги. Завершены вынужденно (из-за исчерпания лимита, галлюцинаций модели, ухода обсуждения в сторону от исходной темы), однако создали ценный результат. 

**Предметные области** выделяются по схеме, описанной [здесь](knowledge-registry.md#1-категоризация-тем). Целесообразно закодировать их с помощью эмодзи.

!!! note "Примечание"
    Диалогам с низкой ценностью, разовым запросам префикс не присваивается

!!! example "Пример № 1"
    [ARC] ✈️ Черногория поездка

!!! example "Пример № 2"
    [P1] 💼 MKDocs material изучение

#### 2. Применение подхода

* **Первичная классификация**: разово добавьте префиксы для всех важных существующих диалогов;

* **Классификация нового диалога**: присваивайте префикс чату только тогда, когда становится понятна его ценность;

* **Актуализация**: обновляйте префикс сразу после изменения статуса задачи.

!!! warning "Внимание"
    Если название диалога не соответствует сути решаемой задачи, помимо добавления префикса следует переименовать диалог.
