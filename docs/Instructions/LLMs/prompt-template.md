В структуре первичного промпта выделяют базовые разделы, актуальные для большинства задач, и ситуативные.

### Базовые разделы

**1. Задача (Task)**

Единственный по-настоящему обязательный раздел. Описывает, что конкретно должна сделать модель. Чем точнее формулировка — тем точнее ответ.

!!! example "Пример"
    Составь план развития карьеры на 2 года для системного аналитика с переходом в продуктовую роль.

**2.  Контекст и входные данные (Context & Input Data)**

Содержит всю информацию, которую модель не может знать сама: предыстория, условия задачи, входные данные. При недостатке контекста модель опирается на собственные допущения, которые могут быть ошибочны для вашей ситуации.

!!! example "Пример"
    Опыт: 4 года работы системным аналитиком в e-commerce, есть опыт работы с продуктовыми командами, но без формальной роли. Цель — перейти в Product Owner в течение 2 лет.

**3.  Формат вывода (Output Format)**

Указывает в каком виде должен быть представлен результат. Без этого раздела модель выбирает формат самостоятельно — и он может не подойти для вашей задачи.

!!! example "Пример"
    Ответ в виде таблицы: этап | ключевые действия | временные рамки | ресурсы

**4.  Ограничения и критерии (Constraints & Success criteria)** 

Содержит правила, ограничивающие пространство возможных ответов, а также критерии качества ответа. Без этого раздела модель может дать формально верный, но неподходящий для вашего случая результат.

!!! example "Пример"
    Не предлагай роли, связанные с публичными выступлениями. План должен быть реалистичен для российского рынка.

**5. Стиль и аудитория (Style & Audience)**

Задает тон, целевую аудиторию и глубину подачи материала. Без этого раздела модель может выбрать тон и уровень детализации, не соответствующий вашим ожиданиям.

!!! example "Пример"
    Пиши для системного аналитика с 4 годами опыта, знакомого с продуктовой разработкой. Тон — деловой, без излишнего оптимизма.

**6.  Пошаговость (Stepwise Thinking)**

Активация цепочки рассуждений (Chain-of-Thought, CoT), побуждающей модель разбивать задачу на последовательные этапы. Позволяет повысить точность ответа при решении сложных многосоставных задач.

!!! example "Пример"
    Сначала определи ключевые навыки, которых не хватает для роли Product Owner. Затем предложи способы их получения. После этого собери всё в итоговый план.

### Ситуативные разделы

**1.  Роль (Role)**

Задает модели экспертную позицию, с которой она подходит к задаче. Наиболее заметно влияет на тон и стиль подачи материала.

!!! example "Пример"
    Ты — карьерный консультант с опытом работы на российском IT-рынке.

**2.  Примеры (Examples)**

Задает требования к структуре результата на основании примеров. Используется, когда точное словесное описание желаемого формата результата затруднено.

!!! example "Пример"
    Генерируй заголовки в таком стиле: 

    Вход: статья про выгорание на работе → Выход: «Почему вы устаёте даже в отпуске» 

    Вход: статья про тайм-менеджмент → Выход: «Вы планируете день неправильно. Вот почему» 

    Теперь сделай то же самое для статьи про удалённую работу.

**3.  Методология (Methodology)**

Указывает конкретный метод или подход, которым должна руководствоваться модель. Используется для тех типов задач, в которых применение определенной методологии дает более полный и структурированный результат.

!!! example "Пример"
    Используй SWOT-анализ для оценки карьерных перспектив системного аналитика в продуктовой роли.

**4.  Валидация (Validation)**

Задает модели инструкцию по проверке результата на соответствие заданным критериям перед выдачей финального ответа. Используется для снижения риска ошибок и пропуска требований.

!!! example "Пример"
    Перед финальным ответом проверь, что описание каждого эндпоинта содержит: метод, URL, параметры запроса, формат ответа и коды ошибок.

**5.  Правила диалога (Persistent Dialogue Rules)**

Задает инструкции, постоянно действующие в рамках всего чата. Используется, когда планируется длительное взаимодействие с моделью в рамках одной задачи.

!!! example "Пример"
    Отслеживай противоречия между моими предыдущими запросами и текущим — сигнализируй, если они появляются.
